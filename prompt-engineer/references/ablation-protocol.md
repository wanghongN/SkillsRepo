# 消融实验协议（诊断"效果不好"）

> 来源：《AI Agents in Depth》中译本 2.4 节与实验 2-4。该实验基于 prompt-engineering 项目、
> 在 Tau-Bench 框架上模拟航空客服与零售客服两个场景，用控制变量法逐个关掉系统组件，
> 测量每个维度对最终效果的贡献。
> 本机参考副本：`E:\AI-Agents-in-Depth-zh-CN.pdf`（完整版）、`E:\AI-Agents-in-Depth-zh-CN_Extract.pdf`（2.4/2.5 摘录）。

## 何时用

Agent 表现不佳时。**先定位，再改**——全面重写会让所有归因线索一起消失。

## 基线配置

先固定一个"全开"的基线，所有消融都与它对比：

```
基线 = 结构化系统提示词 + 完整工具描述 + 专业中立语气
```

每次只关掉一个组件，其余保持字节级不变。

## 三个标准消融维度

| 维度 | 怎么关 | 实测影响 | 判读 |
|------|--------|---------|------|
| 信息组织 | 保留全部规则内容，只打乱组织形式：去掉标题层次，把有序流程拆成无序规则集合 | 任务成功率 **下降超过 30%** | 影响最大的单一维度。规则无序时模型识别不出优先级与依赖关系——"先验证身份再处理退款"被拆散后，Agent 有时就会跳过身份验证 |
| 工具描述 | 保留函数签名与参数定义，移除全部描述性文本 | 工具调用错误率 **增加 45%** | 频繁传无效参数值、误解参数含义。描述不是装饰 |
| 语气与风格 | 换成夸张修辞与极度自信的表达（"没人比我更会订票"），或轻松口吻加大量表情 | 对任务完成率影响**相对有限** | 模型风格适应能力强 → 风格问题**优先级最低**，最后再调 |

## 指标记录表

每个配置都记录，不要只看"感觉变好了"：

| 配置 | 任务完成率 | 交互轮数 | 违规率 | 用户满意度 |
|------|-----------|---------|--------|-----------|
| 基线（全开） | | | | |
| 去掉信息组织 | | | | |
| 去掉工具描述 | | | | |
| 换成另一种语气 | | | | |

指标说明：

- **任务完成率**：能自己跑 case 就自己算，别用主观印象代替。
- **交互轮数**：效率代理指标。轮数明显暴涨，说明模型在上下文里找规则。
- **违规率**：跳过必备步骤、越过红线的比例——组织混乱最先在这里显形。
- **用户满意度**：主观性最强，放最后看。

## 判读与下一步

1. 差距最大的那个维度 = 病灶，按 Path C 的症状表开处方。
2. 各维度差距都不明显 → 问题多半不在提示词，去查工具实现、检索质量或模型能力本身。
3. 改完只回归改动的那一个维度，确认提升确实来自它。

## 常见误判

- **一次改多处**：提升无法归因，也无法回滚。
- **只用 1-2 个 case**：单点噪声太大，看不出 30% 量级的差异。
- **先调风格**：风格对完成率影响最小，先动它等于把预算花在最没收益的地方。
- **把消融当性能评测**：它回答的是"哪个组件重要"，不是"这份提示词能不能上线"。
